OBJETIVO
Ampliar o catálogo Tandem para todos os sistemas e cores Libretro com pacote Android arm64-v8a que sejam tecnicamente integráveis, incluindo as plataformas atualmente encaminhadas a emuladores externos. Incluir Vita3K como experimental prioritário e avaliar outros cores experimentais sem apresentá-los como compatíveis/estáveis por simples presença de binário.

REQUISITO DE DRIVER VULKAN
- Criar seleção opcional de driver Vulkan externo para GPUs Snapdragon/Qualcomm Adreno, especialmente Mesa Turnip.
- A implementação deve ser rootless, por aplicativo, usando libadrenotools e armazenamento privado.
- Não modificar /vendor, partição de sistema, propriedades globais ou driver do aparelho.
- Manter "Driver do sistema" como padrão e opção de recuperação.
- Importar pacote de driver pelo seletor de arquivos Android; validar formato, arquitetura, arquivos e biblioteca antes de ativar.
- Manter drivers isolados por versão/GPU quando possível, rollback e proteção contra ZIP traversal/arquivos inesperados.
- Validar criação de VkInstance, enumeração de GPU e extensões necessárias antes de oferecer o driver como selecionável.
- Só ativar o driver customizado na inicialização da sessão Vulkan; reiniciar a sessão/jogo para aplicar.
- Drivers Adreno não devem ser oferecidos em GPUs Mali/PowerVR/Xclipse. Não prometer compatibilidade entre gerações Adreno.
- Não baixar executáveis/drivers de mirrors não confiáveis automaticamente. O usuário importa um pacote de origem confiável; o app registra origem/nome/hash.

DESCOBERTA TÉCNICA IMPORTANTE
- LibretroDroid já possui VulkanBackend, suporte a cores Vulkan HW render, VulkanDriver, configuração JNI setVulkanConfig e integração CMake com libadrenotools em arm64-v8a.
- GLRetroViewData já contém preferVulkan e vulkanDriver.
- GLRetroView encaminha diretório/nome do driver e hookDirectory (nativeLibraryDir) / scratchDirectory (cacheDir) ao backend.
- GameSessionActivity ainda não injeta configuração de driver no GLRetroViewData; falta camada de gestão/importação/seleção e ligação com a sessão.
- Portanto, não substituir o motor gráfico. Completar e testar o caminho existente.

CATÁLOGO — SISTEMAS EXTERNOS ATUAIS A MIGRAR PARA LIBRETRO
- PlayStation 2: PCEE2 como primeira opção de integração; ARMSX2 como alternativa a avaliar. PCEE2 é experimental, mas documenta controles, saves, states, rumble, disk control e memory monitoring. ARMSX2 não declara suporte a saves tradicionais, controles e memory monitoring no contrato Libretro.
- GameCube: Dolphin Libretro.
- Wii: Dolphin Libretro.
- Nintendo 3DS: Azahar Libretro (preferir ao Citra legado).
- Wii U: Cemu Libretro; fluxo próprio de keys/MLC e sem save states.
- Nintendo Switch: fora do escopo confirmado; não há core Android ARM64 viável verificado.

CATÁLOGO — EXPERIMENTAIS
- PlayStation Vita: Vita3K Libretro — incluir como experimental prioritário. Exige Vulkan 1.1 (ou OpenGL via glcore, conforme core), firmware oficial do sistema e dados do core. Não oferece saves/states Libretro nem memory monitoring; armazenamento de jogos e saves é interno ao sistema emulado.
- PlayStation 3: RPCS3 Libretro — binário Android ARM64 publicado, mas requisitos extremos e validação de uso real obrigatória; manter desativado/experimental no catálogo padrão até confirmar estabilidade.
- Xbox 360: Xenia Edge Libretro — experimental, Vulkan 1.1, requisitos elevados; manter desativado/experimental no catálogo padrão até confirmar estabilidade.
- Não prometer que PS3/Xbox 360 sejam utilizáveis no Motorola Edge 30 Fusion; compatibilidade do core e capacidade do aparelho são avaliações distintas.

REGRAS DE INTEGRAÇÃO ROMM / SAVES / RETROACHIEVEMENTS
- Não presumir que todos os cores suportam save RAM ou states Libretro.
- Preservar o armazenamento interno de consoles que usam estrutura própria (ex.: Vita3K ux0 e PS2 memory cards).
- Mapear saves RomM apenas quando o core oferece save files estáveis e documentados; caso contrário, registrar limitação e não sobrescrever dados do sistema emulado.
- Não habilitar RA Hardcore em cores sem memory monitoring compatível.
- Manter ROMs, BIOS, firmware, keys, memory cards e saves locais; nunca enviar esses dados a terceiros.
- Os arquivos de firmware/BIOS/keys devem ser fornecidos pelo usuário a partir de cópias legítimas; não incluir conteúdo proprietário no APK nem baixar firmware automaticamente.

NOTA SOBRE VULKAN/TURNIP
- A infraestrutura Vulkan já existe em LibretroDroid: VulkanBackend, libadrenotools, setVulkanConfig, VulkanDriver, GLRetroViewData.preferVulkan e GLRetroViewData.vulkanDriver.
- O caminho rootless via libadrenotools é apropriado; o app não precisa alterar /vendor.
- A sessão atual ainda não configura preferVulkan/vulkanDriver de acordo com o core nem apresenta gestão de pacotes externos.
- Vita3K requer Vulkan 1.1 ou OpenGL com glcore conforme renderer; PCEE2 aceita Vulkan/OpenGL/software (Vulkan recomendado). O backend atual do Tandem é GLES para apresentação e oferece contexto Vulkan separado para cores que negociam HW render; cada core precisa ser testado nessa ponte.
- Não implementar fallback silencioso para OpenGL quando um core exige Vulkan. Apresentar erro claro e manter o driver do sistema selecionável.
